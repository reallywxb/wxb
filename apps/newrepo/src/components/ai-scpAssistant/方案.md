# AI 助手接口切换方案（非流式 `aIChatAction/chat.do` + 全功能对齐）

## 📋 背景

当前 Vue3 版本的 AI 助手通过 `/ai/chat` 走独立代理（`aiProxyUrl`），使用 **SSE 流式通信**实现打字机效果。

现需切换为走项目主代理（`proxyUrl`），直接请求后端非流式接口 `/aIChatAction/chat.do`，**并完整实现 Layui 版的多类型回复展示、图片预览、表格导出等功能**。

---

## 🔧 代理配置说明

### 当前代理映射

| 代理路径 | 目标地址 | Rewrite 规则 | 最终请求 |
| --- | --- | --- | --- |
| `/ai` | `aiProxyUrl` (`192.168.20.163:32239`) | `/ai` → `/api/ai` | `192.168.20.163:32239/api/ai/chat` |
| `/spd-api` | `proxyUrl` (`192.168.30.121:32081`) | `/spd-api` → `/` | `192.168.30.121:32081/xxx` |

### 采用方案：复用现有 `/spd-api` 代理（**无需修改代理配置**）

前端请求路径改为 `/spd-api/aIChatAction/chat.do`，经过 `vite.config.mts` 中 `/spd-api` 代理的 rewrite 规则（`/spd-api` → `/`）后，实际请求为：

```
http://192.168.30.121:32081/aIChatAction/chat.do
```

## 🔍 现有逻辑对比分析

### 1. Layui 旧版怎么处理？（`ai-chat.js`）

- **通信方式**：`jQuery AJAX` 同步请求 `../aIChatAction/chat.do`
- **请求参数**：`{ msg: 用户输入, history: JSON.stringify(aiChatHistory) }`（表单格式）
- **响应处理**：等待后端完整返回 JSON 后，在 `success` 回调中解析
- **渲染逻辑**：根据 `result.type` 区分渲染：
  - `sql_query`：表格渲染 + 导出 Excel 按钮
  - `chat_html`：富文本（含 `<img>` 标签）
  - `from_knowledge_base`：知识库回复（润色文本 + 可选 `content_html` + 截图列表）
  - 默认：纯文本
- **图片处理**：`normalizeImageUrl()` 兼容三种图片地址格式，`normalizeHtmlImages()` 替换富文本图片 `src`
- **历史记录**：前端维护 `aiChatHistory` 数组，每次收到完整回复后 `push` 到历史

### 2. Vue3 新版怎么处理？（`mockData.ts` + `tdChatArea.vue`）

- **通信方式**：`fetch` + `ReadableStream` 读取 SSE 流式数据
- **请求参数**：`{ messages, validate: {url, token}, type }`（JSON 格式）
- **响应处理**：`fetchSSE` 函数循环调用 `reader.read()`，逐块解码 `TextDecoder`，通过正则/JSON 解析 `data: {...}` 片段
- **渲染逻辑**：每解析到一个 `text` 片段，立即追加到 `lastItem.content += data`，实现逐字打印效果
- **模型支持**：针对 `dify/deepseek/coze` 三种流格式做特殊解析

## 🛠️ Vue3 版本改造方案

切换为非流式接口后，核心改动是 **移除 SSE 流式解析逻辑，改为标准 JSON 请求与多类型渲染**。

### 步骤 1：改造请求层（`mockData.ts`）

将返回 `Promise<Response>` 的流式封装，改为返回 `Promise<any>` 的标准 JSON 请求。

```typescript
// apps/newrepo/src/components/aiAssistant/mockData.ts
import { useAccessStore } from '@vben/stores';
import { message } from 'ant-design-vue';

export class MockSSEResponse {
  abortController: AbortController;

  constructor() {
    this.abortController = new AbortController();
  }

  // 改为直接返回解析后的 JSON 数据
  async getResponse(inputValue: string): Promise<any> {
    const accessStore = useAccessStore();

    // 使用项目主代理路径 /spd-api/aIChatAction/chat.do
    const res = await fetch('/spd-api/aIChatAction/chat.do', {
      signal: this.abortController.signal,
      method: 'POST',
      headers: {
        'Content-Type': 'application/x-www-form-urlencoded',
      },
      // 参考 Layui 版传参格式
      body: new URLSearchParams({
        msg: inputValue,
      }).toString(),
    });

    if (!res.ok) {
      if (res.status === 401) {
        message.error('登录已过期，请重新登录');
        // 触发登出逻辑
      }
      throw new Error(res.statusText);
    }

    return await res.json();
  }
}
```

### 步骤 2：改造流式处理层（`tdChatArea.vue`）

替换 `fetchSSE` 和 `handleData` 逻辑，移除 `reader.read()` 和逐字追加，增加多类型渲染。

```typescript
// apps/newrepo/src/components/aiAssistant/tdChatArea.vue (handleData 改造后)
const handleData = async (inputValue: string) => {
  loading.value = true;
  isStreamLoad.value = false;
  const lastItem: any = chatList.value[0];

  try {
    const mockResponse = new MockSSEResponse();
    fetchCancel.value = mockResponse;

    const result = await mockResponse.getResponse(inputValue);

    if (result?.success) {
      // 根据 type 区分渲染
      const type = result.type || 'chat';

      if (type === 'sql_query') {
        // SQL 查询结果：表格渲染
        lastItem.content = result.content || '';
        lastItem.tableData = result.data || [];
        lastItem.tableColumns = result.columns || [];
        lastItem.tableCount = result.count || 0;
        lastItem.replyType = 'table';
      } else if (type === 'chat_html') {
        // 富文本回复
        lastItem.content = result.content || '';
        lastItem.contentHtml = normalizeHtmlImages(result.content);
        lastItem.replyType = 'html';
      } else if (result.from_knowledge_base) {
        // 知识库回复
        if (result.content_html) {
          lastItem.contentHtml = normalizeHtmlImages(result.content_html);
          lastItem.screenshots = result.screenshots || [];
          lastItem.replyType = 'knowledge-rich';
        } else {
          lastItem.content = result.content || '收到';
          lastItem.screenshots = result.screenshots || [];
          lastItem.replyType = 'knowledge-text';
        }
      } else {
        // 普通文本
        lastItem.content = result.content || '收到';
        lastItem.replyType = 'text';
      }
    } else {
      lastItem.content = result.message || '抱歉，处理您的请求时出错了';
      lastItem.role = 'error';
    }
  } catch (error: any) {
    if (error.name === 'AbortError') {
      message.info('已停止生成');
    } else {
      message.error('请求失败，请重试');
      lastItem.content = '网络异常，请检查连接';
      lastItem.role = 'error';
    }
  } finally {
    loading.value = false;
  }
};
```

### 步骤 3：新增图片处理工具函数

```typescript
// apps/newrepo/src/components/aiAssistant/utils/image.ts

/**
 * 规范化图片 URL，兼容三种格式：
 * 1. 旧格式 "loadImage.do?path=..." → 补全为 "/spd-api/aIChatAction/loadImage.do?path=..."
 * 2. 相对路径 "../aIChatAction/loadImage.do?path=..." → 转为 "/spd-api/aIChatAction/loadImage.do?path=..."
 * 3. 完整 URL "http://..." 或 "/xxx/loadImage.do?..." → 直接用
 */
export function normalizeImageUrl(url: string): string {
  if (!url) return url;
  // 已经是完整 URL 或以 / 开头的绝对路径，直接用
  if (/^https?:\/\//i.test(url) || url.startsWith('/')) {
    return url;
  }
  // 旧格式：loadImage.do?path=...（没有 aIChatAction 前缀）
  if (!url.includes('aIChatAction/') && url.includes('loadImage.do')) {
    return `/spd-api/aIChatAction/${url}`;
  }
  // 相对路径 ../aIChatAction/... → /spd-api/aIChatAction/...
  if (url.startsWith('../')) {
    return url.replace('../', '/spd-api/');
  }
  return url;
}

/**
 * 规范化富文本 HTML 中的所有图片地址
 */
export function normalizeHtmlImages(html: string): string {
  if (!html) return html;
  return html.replace(/src="([^"]*)"/g, (match, url) => {
    return `src="${normalizeImageUrl(url)}"`;
  });
}
```

### 步骤 4：新增表格导出功能

```typescript
// apps/newrepo/src/components/aiAssistant/utils/export.ts

/**
 * 导出表格数据到 Excel
 * 通过隐藏表单 POST 提交到后端导出接口
 */
export function exportToExcel(
  data: Record<string, any>[],
  columns: string[],
  title: string,
): void {
  const form = document.createElement('form');
  form.method = 'POST';
  form.action = '/spd-api/aIChatAction/exportExcel.do';
  form.style.display = 'none';

  const dataInput = document.createElement('input');
  dataInput.type = 'hidden';
  dataInput.name = 'data';
  dataInput.value = JSON.stringify(data);
  form.appendChild(dataInput);

  const columnsInput = document.createElement('input');
  columnsInput.type = 'hidden';
  columnsInput.name = 'columns';
  columnsInput.value = JSON.stringify(columns);
  form.appendChild(columnsInput);

  const titleInput = document.createElement('input');
  titleInput.type = 'hidden';
  titleInput.name = 'title';
  titleInput.value = title;
  form.appendChild(titleInput);

  document.body.appendChild(form);
  form.submit();
  document.body.removeChild(form);
}
```

## ⚠️ 注意事项

### 1. 接口格式差异

| 对比项 | 原 Vue3 接口 `/ai/chat` | 新接口 `aIChatAction/chat.do` | Layui 旧版 |
| --- | --- | --- | --- |
| **通信方式** | SSE 流式 | 非流式 JSON | 非流式 JSON |
| **请求参数** | `{ messages, validate, type }` | `{ msg, history }` 表单格式 | `{ msg, history }` |
| **响应格式** | `data: {"event":"message","data":{"text":"..."}}` | `{ success, type, content, data }` | `{ success, type, content, data }` |

### 2. 请求参数格式

Layui 版使用 `application/x-www-form-urlencoded` 表单格式传参，需与后端确认：

- 是否支持 JSON 格式请求（`application/json`）
- `history` 参数是否必传

### 3. 多类型响应处理

非流式返回的 `type` 可能包含：

| type | 字段 | 渲染方式 |
| --- | --- | --- |
| `sql_query` | `data`, `columns`, `count` | `a-table` 表格 + 导出按钮 |
| `chat_html` | `content`（HTML 字符串） | `v-html` 渲染富文本 |
| `from_knowledge_base` + `content_html` | `content_html`, `screenshots` | `v-html` + 截图列表 |
| `from_knowledge_base`（无 html） | `content`, `screenshots` | 纯文本 + 截图列表 |
| 默认 | `content` | 纯文本/Markdown |

### 4. 图片地址处理

图片地址需通过 `normalizeImageUrl()` 处理，兼容三种格式：

- `../aIChatAction/loadImage.do?path=...` → `/spd-api/aIChatAction/loadImage.do?path=...`
- `loadImage.do?path=...` → `/spd-api/aIChatAction/loadImage.do?path=...`
- 完整 URL → 直接使用

### 5. 体验降级风险

非流式接口需等待后端完整生成后才返回，用户会看到较长时间的 `loading` 空白。

**应对方案：**

- 确保 loading 动画明显
- 或要求后端开启流式接口
- 或前端增加"正在思考中..."的过渡提示

### 6. 代理路由

确保 `vite.config.mts` 中 `/spd-api` 的 rewrite 规则正确映射到主服务器，请求才会到达 `proxyUrl`。

## ✅ 总结

改造难度：**中**（约 2~4 小时）。

核心工作：

1. 将 `async/await + ReadableStream` 替换为标准的 `fetch().then(res => res.json())`
2. 根据 `result.type` 实现多类型渲染（表格、富文本、知识库图文）
3. 补充图片地址规范化、截图列表、表格导出功能

需注意请求头格式与后端对齐，并确保图片地址通过代理正确转发。
